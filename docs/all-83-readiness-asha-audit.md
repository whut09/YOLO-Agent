# All 83 Readiness and ASHA Audit

## Scope

This audit is offline and CPU/mock-only. It reads the production paper
coverage, the paper execution inventory, the requirements matrix, and the
persistent readiness report. It does not start training, probe CUDA, create a
model result, or promote a mock candidate into production evidence.

The acceptance test is
`tests/test_all_83_readiness_and_asha_acceptance.py`.

## End-to-End Assertions

The CPU acceptance suite verifies:

- inventory, requirements, and readiness all contain the same 83 paper IDs;
- every paper has a paper-specific mechanism or an explicit unresolved reason;
- CPU-passing rows always reach the runtime decision tuple and cannot silently
  disappear;
- explicitly labelled mock-ready fingerprints enter both
  `RoundExecutionPlan` and ASHA with matched controls;
- equal execution fingerprints merge provenance, while distinct fingerprints
  remain separate trials;
- missing teacher evidence, missing source/target domain evidence, hard
  negative evidence gaps, and inference-only routes are not ASHA-eligible;
- protocol mismatch produces no paired metric delta;
- a failed trial does not remove any other trial;
- a deferred/pre-registered identity has no assignment until formal
  `asha_eligible` registration, then recovers through the same identity;
- there is no silent drop between the three production artifacts.

Mock-ready is a routing fixture only. It does not change the production
readiness report and cannot be used to claim runtime readiness, mAP, latency,
model size, or training coverage.

## Guardrails

An ASHA trial is eligible only when the candidate has passed the runtime gate,
has a matched baseline control, and shares the required protocol, split, image
size, fidelity, and dataset identity. A `pre_registered` identity reserves a
recoverable fingerprint but has `status=needs_evidence`, no pending rung, and
no training assignment.

A paired mAP delta is valid only after both candidate and matched baseline
complete under the same protocol. Readiness smoke, paper claims, shadow
assignment metrics, and mock execution do not produce a paired improvement.
